4. Qué perdió el JSON enriquecido
En blueprint_evidence_initiateVirtualAccount.json, los modelos siguen presentes como figuras con contenido estructurado. Además, resultMatrix los clasifica como Actividad / modelo y Dato identificado. Sin embargo, no conserva dos elementos esenciales:
A. Perdió customData
Las figuras del enriquecido no contienen los marcadores:


ENTRADA
SALIDA
``
Por tanto, ya no puede determinarse semánticamente la dirección del modelo.
B. Perdió la membresía de grupos
El enriquecido no conserva una lista utilizable de grupos que declare:


modelo de entrada + API + modelo de salida
La jerarquía muestra que la API y los modelos están en INTEGRACIÓN, pero compartir contenedor padre no demuestra asociación.
C. No creó una asociación equivalente
El enriquecido tampoco agregó una estructura sustitutiva, por ejemplo:


"modelAssociations": [...]
ni propiedades como:


"associatedComponentId": "..."
"modelDirection": "input"
Por ello, la relación que existía en el original no puede reconstruirse completamente desde el enriquecido.2.json

6. Conclusión normativa y técnica
Sí se puede afirmar:
El JSON original contiene evidencia semántica suficiente para asociar determinados modelos de entrada y salida con API concretas, porque conserva tanto los marcadores ENTRADA/SALIDA como la membresía común en grupos que incluyen el componente API. El JSON enriquecido conserva las figuras y su contenido, pero pierde customData y las referencias de grupo, por lo que la dirección y asociación individual quedan No verificables.
Esto significa que el problema no está en el blueprint original, sino en el proceso de enriquecimiento.
