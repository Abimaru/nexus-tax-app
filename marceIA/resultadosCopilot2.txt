M. Definir completitud del inventario por familia
Para poder marcar No cumple por ausencia, el agente necesita saber si la app pudo revisar la totalidad de la población relevante.

No basta con poner:



"unassignedCount": 52
La app debería informar:



{
  "inventoryCoverage": {
    "components": "COMPLETE",
    "connections": "COMPLETE",
    "containment": "PARTIAL",
    "bpmnSubtypes": "PARTIAL",
    "customData": "COMPLETE",
    "modelAssociations": "PARTIAL",
    "deploymentAssociations": "COMPLETE"
  }
}
Porque:

Si conexiones es COMPLETE, la ausencia de una conexión obligatoria puede convertirse en No cumple.
Si conexiones es PARTIAL, la ausencia normalmente conduce a No verificable.
Si los subtipos BPMN son parciales, Inicio o señal no se deben considerar ausentes.
Si las asociaciones de modelos son parciales, un modelo no asociado no demuestra incumplimiento.
Esta distinción es fundamental para tus cuatro estados.

N. Mantener los conflictos, pero no resolverlos arbitrariamente
La sección sourceDiff es útil. No debería eliminarse, pero sí normalizarse:



{
  "conflicts": [
    {
      "entityId": "20QoG0YPgPqR",
      "attribute": "directParent",
      "claims": [
        {
          "source": "JSON",
          "value": "20Qo7gOlA.J_"
        },
        {
          "source": "CSV",
          "value": "Rj0eK9I.Lm5R"
        }
      ],
      "resolution": null
    }
  ]
}
La app no debe transformar esta contradicción en un único parentId. Esta contradicción puede producir No verificable, con calificador Evidencia contradictoria, en las reglas afectadas.
