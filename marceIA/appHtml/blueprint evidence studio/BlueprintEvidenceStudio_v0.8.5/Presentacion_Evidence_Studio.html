Un traductor entre el diagrama y el revisor

Qué es

Una herramienta que se abre en el navegador. Se le entrega el diagrama dibujado en Lucidchart y devuelve un archivo en el que cada figura ya está identificada: es una API, es un servicio, es un evento.

Para qué

Para que la revisión de las 38 reglas de calidad de arquitectura se haga igual cada vez, más rápido y con una explicación para cada conclusión, sin depender de quién revise ni de cómo dibujó cada equipo.

Qué valor da

El asistente de IA recibe hechos, no suposiciones. Si algo no se puede afirmar con evidencia, el resultado dice «no verificable» en lugar de inventar una respuesta.

No le pedimos a la IA que adivine qué es cada figura. Se lo entregamos ya identificado y con su evidencia.

Qué hace el Evidence Studio

Cuatro pasos, todo en su navegador

Cargar

Se indica el nombre del Blueprint y se carga el archivo JSON original exportado de Lucidchart.

Elegir páginas

Se marcan los escenarios (páginas del diagrama) que se quieren enriquecer.

Reconocer

Aplica reglas fijas para saber qué es cada figura, dónde está y con qué se conecta.

Entregar

Descarga el JSON enriquecido, que se carga en el asistente de IA junto con la Skill.

Sin instalación ni red

Es un solo archivo HTML. Se abre en el navegador y el diagrama no sale del equipo.

Reglas fijas

Mismo diagrama, mismo resultado. No hay interpretación libre ni estados de ánimo.

No opina

Reconoce y ordena. Evaluar si algo cumple o no es trabajo de otra pieza (lámina 9).

Reglas que más pesan · 1 de 2

Cómo decide si un bloque es API, servicio o evento

  1. ¿Describe un evento?Su tercera sección trae tipo (Aplicación o Empresarial) y clasificación (Event, Query o Command) → evento de integración. Con solo una parte: candidato.
  2. ¿Se declara microservicio?El nombre empieza o termina en ms, dice «microservicio», o trae TIPO: SERVICIO → servicio. Gana sobre cualquier suposición de API.
  3. ¿Tiene marcador de API o exposición?Un marcador de API agrupado con el bloque, o Public / Private / Partner en la tercera sección → API.
  4. ¿Hay pistas en su zona?Se comparan marcadores sueltos y bloques de la misma zona: coinciden → API; no coinciden → candidato; no hay marcadores → servicio. En el dominio productor nunca se declara API.
  5. Ninguna señalQueda como candidato o sin tipo. No se adivina.
Pruébelo: elija una figura y vea qué paso la decide
Reglas que más pesan · 2 de 2

Contenedores, capas, comandos y lo que se deja fuera

Contenedores

Los dominios (Integración, Productor, Sistemas externos) son contenedores padre. El hijo principal es el que señala el escenario y representa el servicio que se documenta. Dentro del hijo no se clasifican API, servicios ni eventos.

Sistema externo auxiliar

Todo grupo BPMN dentro de un dominio, tenga o no nombre. Sin nombre, la regla EXT-001 se marca como incumplida.

Capa de tópicos

Un contenedor que contiene directamente un evento de integración certificado. El nombre no la certifica: la certifica lo que contiene. Cada evento queda asociado a su capa.

Comando y modelo

Una actividad BPMN conectada a una API, servicio, gestor o auxiliar es un comando. Una marcada ENTRADA o SALIDA es un modelo. Si no cumple ninguna, se anota sin tipo y puede dejar una regla no verificable.

Gestor de colas

Si el nombre menciona cola, MQ, Kafka o Rabbit se propone como candidato a gestor de colas. El nombre sugiere, no certifica.

Lo que se deja fuera

La leyenda de notación y los bloques de descripción de API no se exportan: son ruido. Color, posición y tamaño no sirven para tipar. El nombre de una figura es su primer texto no vacío.

Cada figura recibe además un rol: principal (la API o el servicio que protagoniza el escenario) o invocado (cualquier otro).

Quién hace qué

Tres piezas, cada una con una sola responsabilidad

Studio
Como un topógrafo: mide y etiqueta
  • Reconoce figuras y su certeza
  • Relaciona contenedores y conexiones
  • Entrega el JSON enriquecido
  • No evalúa reglas ni da veredictos
Skill
Como el reglamento y su inspector
  • Contiene las 38 reglas de la analista
  • Define cómo se decide cada estado
  • Trae una ficha operativa por regla
  • No reconoce figuras por su cuenta
Agente de IA
Como quien redacta el informe
  • Hace las preguntas puntuales a la analista
  • Cierra cada regla con su justificación
  • Cita siempre «Nombre (id)»
  • No corrige tipos ni los infiere por nombre o color
Diagrama→Studio→JSON enriquecido→Skill + Agente→Informe por regla

Las respuestas de la analista a las preguntas del agente se registran como «declarado por analista», con la figura y la página a la que corresponden.
